# SafeNight 데이터 출처와 갱신 기준

정리 기준: 2026년 11월 4일 KST. 원천의 **관측·기준일**, 제공기관 페이지의 **수정일**, SafeNight의 **조회·수집 시각**을 구분합니다. 매일 확인한다는 것은 원천에 새 자료가 생겼는지 점검한다는 뜻이며, 제공기관이 매일 새 기준의 자료를 발행한다는 뜻은 아닙니다.

## 시설의 일일 변경 확인

시설 원천 네 종류는 매일 **03:15 Asia/Seoul에 GitHub Actions가 수집**하고, **04:00 Asia/Seoul에 Sites가 검증·DB 반영**하도록 두 일정을 등록했습니다. 기존 S-DoT 매일 03:00 일정과는 별개입니다. 정부 파일 호스트를 Sites Worker가 직접 호출하면 시간 초과가 발생해 공개 자료를 수집하는 실행 위치를 GitHub Actions로 분리했습니다.

2026-11-04 [실제 GitHub 수집](https://github.com/roberYM11/safenight/actions/runs/41836099458)과 Sites 운영 DB의 네 단계 반영을 확인했습니다. 내용이 같아 기존 스냅샷은 유지했고, `checked_at`은 `2026-11-04T13:16:25.234Z`로 갱신했습니다. Sites 첫 예약은 **2026-11-05 04:00 KST**이며, 이번 확인은 push로 시작한 수집과 직접 실행한 DB 반영의 결과입니다. 미래 예약 실행 성공이나 정확한 시작 시각을 보장하는 의미는 아닙니다. [운영 검증 기록](../backend/VALIDATION.md)에 이후 결과를 남깁니다.

현재 확보한 시설 스냅샷은 송파구 조명 11,269행, 서초구 보안등 10,692행, 송파구 CCTV 1,974행, 서초구 CCTV 6,397행입니다. 이는 내려받아 검증한 **설치 기록 행 수**입니다. CCTV 화면 수치는 반경 안에 있는 행의 `카메라대수`를 합산하며, 행 수를 카메라 대수나 물리적 지점 수로 바꾸어 부르지 않습니다.

일일 작업은 원천 메타정보와 실제 파일을 확인하고 문서·조회 이력·정정된 스냅샷을 보존합니다. 수집기는 [고정 공개 미러](https://raw.githubusercontent.com/roberYM11/safenight/safenight-facility-data/manifest.json)에 문서 목록을 게시합니다. Sites는 한 작업의 manifest를 고정하고 공식 URL과 다운로드 연결, 문서의 SHA-256·크기를 다시 검증합니다. 네 원천은 같은 manifest로 처리하며, 수집 시각의 한국 날짜가 작업일과 다르면 전날 자료를 오늘 확인한 것으로 기록하지 않습니다. 36시간 최대 경과와 5분 미래 오차 한도도 검사합니다.

네 원천을 모두 검증하기 전에는 현재 스냅샷을 교체하지 않습니다. 수집·검증 실패 시 이전 정상 자료를 유지합니다. 제공기관 자료가 같으면 무변경으로 기록하며, 오래된 원천 기준일을 조회한 오늘 날짜로 바꾸지 않습니다.

범위와 해석은 다음과 같습니다.

- 반경 1km 집계는 현재 확보한 송파구·서초구 설치 기록에 한정합니다. 다른 자치구나 경계 지역의 미등록 자료까지 완전하게 포괄하지 않습니다.
- 반경에 기록이 없으면 `NO_RECORDS`와 `null`입니다. 실제 시설이 없다는 뜻의 0으로 해석하지 않습니다.
- 조명 위치는 현재 점등·고장·밝기 측정 자료가 아닙니다.
- CCTV 좌표 일부는 반올림돼 있어 거리·반경 집계에 오차가 있습니다. 현재 작동, 촬영 범위, 영상·IP 주소는 알 수 없습니다.
- 시설이 많다는 이유만으로 현재 점수를 자동으로 높이지 않습니다.

## 인구 추정치의 공간·시간 범위

[서울시 공식 안내](https://data.seoul.go.kr/dataVisual/seoul/guide.do)는 통신사 기지국 신호를 가공한 구역 추정 인구임을 설명합니다. 분당 통과 인원, CCTV에서 검출한 사람 수, 개인의 이동 경로가 아닙니다. 실제 현장 인원과 차이가 있을 수 있으며, 단기 체류 외국인 등 원천의 제외 조건도 있습니다.

선택 좌표가 공식 폴리곤 안에 있으면 `CONTAINS`로 해당 구역을 표시합니다. 밖이면 실제 경계까지 최단거리가 **250m 이내**인 가장 가까운 구역만 `NEARBY_AREA`와 거리를 붙여 참고값으로 표시합니다. 구역 중심점이나 사각 범위로 포함 여부를 대신하지 않으며, 검색 좌표도 구역 안으로 옮기지 않습니다. 250m를 넘으면 `NO_COVERAGE`입니다.

원문을 R2에 보존하고, 구역 코드·이름·관측 시각·최소/최대값을 검증한 뒤 D1 관측 이력과 현재 캐시에 저장합니다. 캐시는 10분이며, 원천 관측이 **30분을 초과**하거나 대체 자료이면 `STALE`입니다. 갱신 실패 시 DB의 지난 자료를 보여 줄 수 있지만 현재 집계처럼 표시하지 않습니다. 정상적으로 관측된 0과 미확보 `null`도 구분합니다.

이 경로는 **사용자가 선택한 구역의 요청 시 조회**입니다. 전체 121구역의 정기 전수 수집과 장기간 인구 시계열 확보를 완료한 것은 아닙니다.

## 장소 점수의 공간 결합과 현재 모델

장소명·주소는 실제 Photon / OpenStreetMap 응답으로 좌표를 찾습니다. 역명 검색은 철도역을 우선해 동명 버스정류장과 구분합니다. 검색 결과가 없거나 제공자가 실패하면 다른 임의의 좌표나 고정 점수로 대체하지 않습니다. Photon 공개 서버는 [합리적 요청량의 프로젝트 사용](https://github.com/komoot/photon)을 허용하지만 가용성을 보장하지 않으므로, 서버 캐시와 제출 기반 요청을 사용합니다. 데이터 출처는 [OpenStreetMap 기여자·ODbL](https://www.openstreetmap.org/copyright)로 표시합니다.

선택 좌표 반경 **1,500m** 안에서 현재 모델이 지원하고 관측이 유효한 센서를 가까운 순으로 최대 8개 사용합니다. `1 / max(25, 거리m)^2`를 정규화한 가중 평균이며, 사용 센서의 거리·가중치와 관측 시각 범위를 함께 확인할 수 있습니다. 관측이 30시간을 넘거나 결측·지원 밖이면 제외합니다. 이는 주변 센서의 추론값을 보간한 참고값입니다.

현재 모델 입력은 **조도와 소음 두 가지**이고, 대상 `safety_index`는 기존 계산식으로 만든 지표입니다. 실제 범죄·사고 발생의 정답 자료가 아닙니다. 시설과 인구는 현재 `score_included:false`인 주변 정보이며, 새 모델에 이미 반영한 것처럼 설명하지 않습니다.

다음 모델은 자료를 누적하고 기준일·시공간 결합·결측·지역 대표성을 검증한 뒤 별도로 학습할 계획입니다. 목표값과 독립 평가 기준을 정하고 기존 기준선과 비교해 통과한 후보만 교체합니다. 새 데이터가 들어오는 즉시 반복 학습하거나, 서로 다른 시점의 시설·인구 기록을 무조건 한 행으로 합치지 않습니다.

## 라이선스와 재현

S-DoT·서울시 인구·구역 경계는 각 공식 페이지의 공공누리 제1유형 출처표시 조건을, 확보한 시설 자료는 공공데이터포털의 이용허락범위를 따릅니다. OpenStreetMap은 ODbL 출처와 조건을 별도로 확인합니다. API 키·토큰·DB 덤프는 공개 자료에 포함하지 않습니다.

시설 초기 자료의 원천 정보·기준일·조회 시각·CSV 원문 SHA-256은 `cloud/app/server/data/context-facilities.json`에, 인구 경계의 배포일·원문 SHA-256은 `population-areas.json`에 기록합니다. 일일 시설 갱신 결과는 운영 DB 스냅샷과 공개 미러 manifest에 보존합니다. 시설 CSV와 다운로드 응답 JSON은 공개 미러와 운영 R2에 원문으로 보존합니다. 포털 메타데이터·다운로드 페이지는 필요한 항목만 추출해 보존하며, manifest에 표현 유형과 원문 해시·추출본 해시를 나누어 기록합니다. 전달받은 추출본의 해시는 Sites가 다시 검증하지만, 추출본만으로 전체 원문을 복원하거나 원문 해시를 재검증할 수는 없습니다. 관측·스냅샷 이력은 운영 저장소에서 관리합니다. 경계 파일은 `scripts/refresh-population-areas.mjs`, 시설 초기 자료는 `scripts/refresh-context-data.mjs`로 재현하며, 운영 시설 갱신은 인증된 내부 API를 사용합니다.

검증 완료 여부는 [backend/VALIDATION.md](../backend/VALIDATION.md)의 실행 기록과 구분해 확인합니다. 이 문서는 현재 계약·출처를 설명하며, 아직 실행하지 않은 정기 일정이나 장기 운영의 성공을 미리 주장하지 않습니다.
