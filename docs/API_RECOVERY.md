# SafeNight API 재연결 메모

확인일: 2026-10-30. 현재 확인된 데이터 제공처와 복구 순서입니다. 인증키를 새로 발급하거나 배포 사이트에 적용한 상태는 아닙니다.

## 1. 먼저 복구할 연결을 구분하기

원본 분석은 Drive CSV를 읽는 방식이므로 데이터 분석을 다시 확인하는 데 모든 실시간 API가 필요한 것은 아닙니다. 웹사이트가 표시되지 않는 문제는 지도 타일, 환경 데이터, 파일 접근을 나누어 확인해야 합니다.

| 연결 | 현재 확인한 사실 | 다음 조치 |
| --- | --- | --- |
| S-DoT 환경정보 | 기존 자료와 별도로 ‘환경정보 (실시간)’ 공식 페이지가 존재 | 최신 명세와 기존 입력 필드의 대응 확인 |
| CCTV 원본 Drive 파일 | 노트북에 기록된 파일 ID를 현재 연결 계정으로 읽으면 404 | 삭제·권한 문제를 구분하고 접근 가능한 원본 복구. 새 API 키만으로 해결되는 문제는 아님 |
| 가로등·보안등 | Drive의 저장 파일과 노트북 활용 기록 확인 | 공식 출처·기준일·좌표 필드 확인 후 갱신 |
| 지도 타일 | 현재 배포 소스·브라우저 요청 미확인 | 실제 제공사, 요청 URL, 응답 이미지, 인증·도메인 조건 확인 |
| 웹 실행 환경 | 원본 배포 소스와 설정 미확인 | 저장소 또는 편집 가능한 사이트 링크에서 실행·배포 설정 확인 |

CCTV 파일 404는 ‘현재 연결된 계정으로 해당 ID를 찾지 못했다’는 의미입니다. API 폐지나 파일 삭제로 확정하지 않습니다.

## 2. S-DoT 최신 제공처

- [스마트서울 도시데이터 센서(S-DoT) 환경정보 (실시간)](https://data.seoul.go.kr/dataList/OA-22833/A/1/datasetView.do)
- [기존 S-DoT 환경정보 페이지](https://data.seoul.go.kr/dataList/OA-15969/S/1/datasetView.do)
- [서울 열린데이터광장 인증키 신청](https://data.seoul.go.kr/together/mypage/actkeyMain.do)
- [공식 API 이용 안내](https://data.seoul.go.kr/together/guide/useGuide.do)

실시간 환경정보의 공식 서비스명은 `sDoTEnv`입니다. 공식 명세의 XML 요청 형식은 다음과 같습니다. 아래는 키를 포함하지 않는 형식 예시이며 실제 호출 성공을 검증한 URL이 아닙니다.

```text
http://openapi.seoul.go.kr:8088/(인증키)/xml/sDoTEnv/1/5/
```

발급 페이지에서 서울시 계정으로 로그인한 뒤 일반 인증키를 신청할 수 있습니다. 기존 키가 있다면 상태와 제한 사유부터 확인합니다. 공식 안내에는 계속 이용하려면 활용사례에 콘텐츠를 등록하도록 안내되어 있으므로 해당 계정의 이용 조건도 함께 확인합니다.

신규 제공 페이지는 시간 단위로 수집된 자료의 실시간 제공을 설명합니다. 연속적인 초 단위 관측으로 해석하면 안 됩니다. API 조회 범위와 과거 파일 제공 방식도 구분해야 합니다.

## 3. 키를 연결하기 전에 확인할 데이터 차이

기존 코드에 새 서비스명만 바꾸면 같은 결과가 보장되는 것은 아닙니다.

1. 센서 식별자, 측정시각, 실제 조도·소음의 최소·평균·최대값을 명시적으로 선택합니다. 원시 CSV는 헤더 58열/데이터 64열이며 기존 학습 입력에 6열 이동이 발생한 것을 3,713행 전체 대조로 확인했습니다. 과거 가공 CSV의 열 이름을 그대로 신뢰하지 않습니다.
2. 기존 `×1000` 변환을 제거한 뒤 실제 소음(dB) 필드를 사용합니다. 과거 ‘소음’으로 사용한 값은 y축 진동이었습니다. 공식 원자료의 진동 단위 정정은 `mm/s → g`이며 소음 변환이 아닙니다. [원시 자료 검증 기록](PROJECT_EVIDENCE.md)을 참조합니다.
3. 최신 센서 위치정보로 결합하고, 센서·시각별 중복과 결측을 확인합니다.
4. 신규 페이지의 `DATA_NO` 설명에 따르면 동일 센서·시각의 실시간값(1)과 지연·보정값(2)이 함께 존재할 수 있으며 2가 최종 측정값입니다. 새 API 처리에 이 규칙을 반영합니다. 이를 과거 CSV 중복의 원인으로 단정하지 않습니다.
5. 잘못된 입력으로 학습한 기존 모델에 새 자료를 바로 넣지 않습니다. 변수 의미·순서·단위·분포와 시설 중복을 확인한 뒤 재학습·독립 평가를 진행합니다. 이번에 수행한 복원 입력 진단은 배포 모델 복구와 별개입니다.

## 4. 사이트에 다시 연결하는 순서

1. 원본 웹 소스에서 지도 타일과 환경 데이터 요청을 각각 확인합니다. 브라우저의 실패한 요청·상태·오류 본문을 기록해 원인을 나눕니다.
2. S-DoT 키 상태를 확인하고 필요한 경우 재발급합니다. 실제 키는 공개 README나 저장소에 올리지 않고 실행 환경에 설정합니다.
3. 공식 문서에 제시된 요청으로 소량 응답부터 확인한 뒤 필드와 시각을 검증합니다. HTTP 상태뿐 아니라 API의 결과 코드와 실제 행을 확인합니다.
4. 웹의 HTTPS 환경에서 공식 문서의 HTTP 요청을 직접 사용할 수 있는지, CORS·혼합 콘텐츠 문제가 있는지 확인합니다. 필요하면 서버 측 수집과 캐시를 통해 연결합니다.
5. 지도는 타일 응답이 200이어도 실제 지도가 그려지는지 확인합니다. 오류 문구가 그려진 이미지는 정상 지도가 아닙니다. 제공사를 변경한다면 출처 표시·사용 조건도 확인합니다.
6. 저장된 과거 자료로 확인하는 화면과 최신 API 화면을 구분하고, 데이터 기준시각·결측 상태를 표시합니다.
7. 원본 프로젝트에 저장한 뒤 새로고침하여 지도·시설·지수·오류 상태가 실제로 유지되는지 확인합니다.

완료 기준은 ‘키 발급’이 아니라 **새 데이터를 정상적으로 읽고, 원본 사이트에서 위치·측정시각·점수가 올바르게 표시되는 것**입니다. 이번 작업에서는 공식 재연결 경로와 필요한 점검사항까지 정리했습니다.
