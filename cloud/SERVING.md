# Sites 배포본의 관측과 모델 서빙

이 배포본은 현재 SafeNight 지도 화면과 서버 측 추론을 Sites에서 실행한다. Python·PostgreSQL 수집 서버를 Cloudflare Workers에 그대로 올리는 방식이 아니다. 기존 수집 서버와 이력 DB는 원래 저장소에 보존한다.

## 실제 데이터와 갱신 범위

`app/server/serving.ts`는 D1의 게시된 최신 관측과 관측 시점에 유효한 위치 revision을 읽는다. `app/server/cloud/`가 일별 수집, R2 원문 보존, D1 staging과 원자적 게시, 누락·정정 구간 재검사를 담당한다. 코드에 포함된 초기 관측 JSON이나 저장된 점수를 읽는 경로는 제거했다.

이전한 관측 이력의 원래 시각·좌표·payload·raw SHA와 native legacy ID를 보존한다. 전체 PostgreSQL 백업도 R2에 별도로 보관한다. 새로 받은 원문은 파싱 전에 보존하며, 모든 페이지를 확인한 뒤에만 현재값과 checkpoint를 바꾼다. 수집 중인 부분 자료를 지도에 노출하지 않는다.

`GET /api/map`은 현재 시각에 실제 모델을 적용하고, 30시간을 넘긴 관측은 점수를 `null`, 상태를 `STALE`로 반환한다. `data_status: cloud`와 마지막 성공한 클라우드 수집의 `captured_at`을 반환하며, 관측 자체의 시각은 별도로 유지한다. 페이지 새로고침은 수집이나 재학습을 시작하지 않는다.

정기 작업의 인증·재개·완료 확인 절차는 `public/CLOUD_OPERATIONS.md`에 있다. 센서 위치 파일의 새 버전 자동 탐지는 현재 수집기 범위에 포함하지 않는다.

## 추론 구현과 모델 교체

`app/server/forest.ts`는 기존 Python 서빙의 데이터 전용 RF JSON 어댑터다. 모델은 `app/server/data/model.json`, manifest는 같은 폴더의 `manifest.json`에 있다. 서버 코드에서만 참조하며 HTTP로 모델 업로드나 실행 코드를 받지 않는다.

- SHA-256과 manifest 버전, 입력 목록, 센서 위치·범위, 트리 수와 평가 센서 분리 여부를 확인한다.
- 트리 참조가 앞으로만 진행하는지 검사해 잘못된 참조와 순환을 거부한다.
- `Math.fround`로 입력을 float32로 변환하고 기존 `<=` 분기·순차 합계·산술평균을 유지한다.
- 학습 센서 ID, 학습 좌표에서 250m 이내, 학습에서 관측한 조도·소음 범위를 만족할 때만 추론한다.
- 결측·미래 관측·입력 계약 불일치·오래된 자료·지원 범위 밖 상태에서는 임의 점수를 만들지 않는다.

같은 형식의 모델을 바꿀 때에는 두 모델 파일을 한 묶음으로 교체하고 fixture를 갱신·검증한 뒤 Sites의 새 버전을 배포한다. 알고리즘을 바꾸면 `forest.ts`의 어댑터도 교체해야 한다. 새 입력 변수가 필요한 경우 관측 자료와 해당 계약도 변경해야 한다. 서버는 요청마다 학습하지 않는다.

## 검증

```sh
node --test tests/serving.test.mjs
npx tsc --noEmit
```

서빙 fixture 시험은 16개다. Python의 원래 `ForestRuntime`으로 생성한 실제 관측 1,169개와 임계값 직전·정확히 일치·직후 입력 72개를 사용해 상태와 반올림 전 점수가 일치하는지 확인했다. 숫자 차이는 1e-12 미만이어야 한다. float32 변환을 없애면 실제로 값이 달라지는 임계값 사례도 포함한다.

관측의 30시간 유효기간 경계와 만료, 필수 입력 결측, 지원 범위 밖, 센서 이동, 미래 시각, 모델 미등록, 해시 변조, 해시가 맞지만 순환 참조가 있는 트리도 확인한다. fixture는 서비스에서 보여 주는 데이터를 대체하지 않는다.

이 검증은 이식된 추론 코드가 기존 계산을 재현하는지에 관한 것이다. 현재 출력은 기존 `safety_index`를 학습한 실험용 환경 안전도이며, 실제 범죄·사고 확률의 타당성이나 운영 부하 성능을 보장하지 않는다.
