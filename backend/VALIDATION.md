검증일: 2026-11-04 KST. 앞부분은 CCTV 영상·Docker 제거와 20:30 클라우드 이전 시점의 기준선이다. 같은 날 추가한 장소 검색·시설 설치자료·구역 인구·일일 갱신 결과는 뒤의 추가 검증에 기록한다. 코드 검사, 실제 저장소 시험, 원천 실수집, 배포 서버 검증을 구분한다.

위 수집 결과는 PostgreSQL 16.2에서 확인했다. SQLite 대체 시험이 아니다. 관측 revision 수는 서로 다른 장소의 수와 다르다. 같은 응답의 중복과 정정된 revision을 구분하고, 원문과 실패 이력도 보존했다.

원천의 작은 시계 역전은 관측 시각을 바꾸지 않고 품질 필드에 기록한다. 입력 형식·페이지·시간 범위를 검증하지 못하면 완료 지점을 전진시키지 않는다.

## 배포와 클라우드 운영 확인

사이트 주소: [SafeNight](https://safenight-seoul-2026.true-tang-8939.chatgpt.site/).

클라우드 코드의 저장소는 D1과 R2이며, 모델 추론은 서버에서 실행한다. 인증된 import 경로를 통한 기존 데이터 이전은 완료했고 배포 서버에서 다음 값을 다시 읽어 확인했다.

| 이관 대상 | 배포 저장소에서 확인한 값 |
|---|---:|
| S-DoT 관측 revision | 24,715개 |
| 센서 위치 revision | 1,170개 |
| 전체 불변 revision | 25,885개 |
| 현재 선택된 관측·위치 포인터 | 25,885개 |
| 활성 원문 객체 | D1 메타데이터 33개와 대응하는 R2 원문 |

과거 CCTV 응답 원문은 활성 수집 자료와 분리해 R2 백업에 보존했다. 전체 PostgreSQL SQL 압축 백업도 R2에 보관했다. 이전 과정에서 원문 digest와 원래 revision의 legacy ID를 유지했다. 8000·8001 로컬 서버와 SafeNight 전용 Colima 실행을 중지한 상태로 클라우드 이전을 마무리했다.

새 원천 페이지는 R2에 먼저 보존한 뒤 D1에 stage하며, 전체 검증이 끝난 작업만 현재값과 checkpoint에 게시한다. 로컬 API와 Docker를 중지한 상태에서 Sites 서버가 2026-11-03 KST 하루의 S-DoT **29,200행을 직접 수집**했고, 2026-11-04 20:30 KST에 성공 상태를 확인했다. 이번 수집에서 2,700개 revision을 추가했으며, 배포 DB를 다시 읽은 결과 전체 revision 28,585개·현재 포인터 28,585개·활성 원문 메타데이터 180개였다. 위 표는 수집 전 이관 수치다.

Sites에 연결된 클라우드 일정 `SafeNight 공공데이터 수집`을 **매일 03:00 Asia/Seoul, 활성 상태**로 저장하고 다시 조회했다. 첫 예약 시각은 2026-11-05 03:00이며, 이 기록 시점에는 아직 예약 실행 전이다. 정기 실행 자체의 성공을 미리 주장하지 않는다. 데이터 이전, 이번 실제 원천 수집, 일정 저장을 각각 확인한 결과다.

운영자 쓰기 경로는 Site 접근 권한과 별도 토큰을 요구한다. 키·토큰은 Sites 비밀 설정에만 두며, 저장소·브라우저 코드·일정 프롬프트에 포함하지 않는다. 정기 작업 기준은 매일 03:00 Asia/Seoul이고, 완료된 전날·누락 구간·최근 정정 여부를 처리한다.

## 화면과 현재 범위

지도·관측 지점 검색·실험용 표시·관측 시각·조도·소음은 유지하고, CCTV 버튼·주변 조회·영상·인원 검출 경로는 제거했다. 오래된 관측과 입력 부족 상태에서 점수를 만들지 않는다. 모델 버전·평가 수치·수집 진단은 일반 화면에 노출하지 않는다.

새 관측은 모델을 자동 재학습하지 않는다. 이 기준선 시점에는 센서 위치 파일 새 버전 자동 탐지, 가로등·보안등 수집, 임의 주소의 거리 가중 평가, 안전 경로·실제 SOS 전송을 완료 범위에 포함하지 않았다. 이후 완료한 항목은 아래에 별도로 기록한다. 실제 안전 예측력과 운영 부하·장시간 장애 복구는 별도 평가 대상이다.

정부 파일 호스트를 Sites Worker가 직접 요청하는 방식은 실제 시간 초과로 실패했다. 이 실패 이력을 남기고, GitHub Actions에서 공개 원천을 수집한 뒤 Sites가 고정 GitHub 경로의 자료를 다시 검증하도록 실행 위치를 분리했다. CSV·내려받기 응답은 원문이고, 포털 메타데이터·내려받기 페이지는 필요한 항목만 추출한 문서다. manifest에 원문 해시와 추출본 해시·표현 유형을 구분한다. 원천 URL·다운로드 연결·CSV·해시·크기·한국 날짜를 검증하고, 한 작업은 같은 manifest로만 네 단계를 진행한다. 실패하면 이전 정상 자료를 유지한다.

시설 수집은 GitHub cron `15 18 * * *`(**03:15 Asia/Seoul**), DB 반영은 Sites의 `SafeNight 시설자료 매일 갱신`(**04:00 Asia/Seoul**)으로 저장했다. Sites 일정 ID는 `Automation_1977ce3f68b88191bdc37914412e82af`이며 다시 조회해 활성 상태를 확인했다. 첫 예약은 **2026-11-05 04:00**이다. 오늘 확인한 것은 실제 push로 시작된 GitHub 수집과 동일 DB 반영 경로의 직접 실행이며, 아직 미래의 예약 실행 성공이나 정확한 시작 시각을 보장하지 않는다. 기존 S-DoT 03:00 일정은 유지한다.

추가 시설은 송파구·서초구의 부분 자료다. 잠실역 검색 좌표 반경 1km에서 가로등 425개·보안등 608개·CCTV 483대를 확인했다. 카메라 대수는 설치 행 수와 다르다. 확보하지 않은 지역은 0으로 만들지 않는다. 송파 조명 기준일 2021-11-22, 서초 보안등 2024-05-13, 두 구 CCTV 2026-05-01을 화면에 그대로 표시한다. 매일 확인해도 과거 자료의 기준일이 새 날짜가 되지는 않는다.

현재 모델은 계속 조도·소음으로 기존 `safety_index`를 재현한다. 새 시설·인구는 함께 표시하고 이력을 쌓으며, 사용자의 선택대로 누적·결합·대표성 검증 후 새 모델 후보를 평가한다. 실측 범죄 위험·분당 통행량·전 지역 시설 확보나 새 입력의 예측 성능을 검증했다는 주장은 하지 않는다.

추가로 기존 Python CI의 두 환경 차이를 실제 실패로 확인하고 수정했다. 첫 실행의 asyncpg 드라이버는 시험 격리용 libpq `options`를 거부해 13개 setup 오류가 발생했으므로 시험용 DSN만 이미 설치된 psycopg로 맞췄다. 이후에는 같은 시각을 UTC와 KST의 문자열 접두어로 비교하던 시험 1개가 실패했다. 실제 PostgreSQL UTC 세션에서 재현한 뒤 시간대가 있는 datetime의 동등성을 확인하도록 수정했다. UTC·Asia/Seoul 두 경우마다 기존 연결을 닫고 새 연결의 `SHOW TIME ZONE` 값까지 검사한다. 실제 로컬 PostgreSQL과 원격 CI에서 최종 **77개 통과**를 확인했으며, 앱 시간 변환·모델·수집 코드는 이 시험에 맞추어 변경하지 않았다.
